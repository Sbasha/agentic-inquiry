# Agentic Inquiry implementation plan

[DESIGN.md](DESIGN.md) defines the required outcomes. This sequence contains open acceptance work only.

1. **Native lifecycle acceptance (R6, R7).** Observe capture, durable receipts, duplicate delivery, automatic recall and compaction in actual enabled Codex/Pi sessions. Use normal native project trust and explicitly owned integration settings. Keep discovery, direct commands, tool use and lifecycle behavior separate. Missing stable host event identity requires the documented explicit capture command. Do not fabricate hook payloads as native evidence.

2. **Remaining platform and input coverage (R2, R3, R9).** Run installed public journeys on Linux and any required format/language or encrypted/malformed input classes not covered by available real material. Retain component evidence separately and record unavailable live coverage as unverified.

3. **Independent outcome comparison (R8).** Freeze independently owned tasks, corpus, atomic-fact rubrics, thresholds, model/effort, tools, context and execution limits. Preserve all attempts, failures, null usage and setup/grading costs. Calibrate judgments and report paired confidence intervals before making a no-quality-loss claim. Do not inspect sealed questions or run a paid study without separate authorization and a spending ceiling.

## Evidence

Keep evidence in Git-ignored machine-readable artifacts. Link each required outcome to observable behavior and its remaining limits. Component checks and local retrieval timings cannot establish comparative answer quality. Installation, native use, comparison and publication are distinct evidence states. Publication and remote changes require their own authorization.

Use real available source material through installed public operations. Edit/delete recovery exercises use explicitly identified disposable copies and preserve originals. Component checks may isolate failures; do not present them as live acceptance. No Markdown change journal is required.
