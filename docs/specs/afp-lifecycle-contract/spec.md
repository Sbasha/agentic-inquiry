## Objective

A coding-agent harness (Claude Code, Codex or Pi) that has the AFP `agentic-inquiry` pack installed drives Agentic Inquiry through one executable and two verbs. `ai capabilities --json` tells the adapter what this runtime supports; `ai integration hook --client <client> --event <event>` receives one bounded JSON request per native lifecycle event on stdin and answers with one JSON object on stdout: a status, a rendered context block with byte accounting, receipts that carry durable identifiers, the work still pending and any errors. An operator enables the integration per project and client with `ai integration enable`, inspects it with `ai integration status` and `ai status`, commits queued work with `ai integration reconcile`, removes retained records with `ai integration purge`, and connects a stdio MCP client with `ai mcp`. Success for the harness user: a session start shows the project's recent memories inside a stated byte budget, an edit or a saved observation yields a receipt they can inspect later, a repeated delivery of the same event never creates a second record, a project that never opted in costs no ledger open and no heavy import, and nothing runs, listens or downloads unless they asked for it.

## Vocabulary

- **Project identity**: the 16 lowercase hex characters in `<project_root>/.agentic-inquiry/project.toml`, written by `enable`, meant to be committed. It names the ledger directory `INQUIRY_HOME/projects/<id>/` and every binding. It is not a storage namespace.
- **Storage namespace**: the bound environment's merged `storage.default_project_id` (`default` from `config/default.yaml` unless the environment overrides it), validated with `validate_project_id` and recorded in the binding at `enable` time; an environment without one cannot be enabled, because an empty namespace means every project in the store.
- **Project-local environment**: an environment whose resolved `config_path` lies under `<project_root>/.agentic-inquiry/`, as `ai setup local <name> --workspace <project_root>` and `/ai:setup` create it. Only a project-local environment can be bound, so each project's store is its own and recall never crosses projects.
- **Ledger home**: `INQUIRY_HOME` when set, else `~/.agentic-inquiry`, the same rule as `env_resolver.get_global_dir`. Recall filters, capture commits, refresh commits and `ai mcp --project-id` use it, so the integration shares one namespace with `ai index`, `ai search` and the `/ai:*` skills in that environment.
- **Binding**: the ledger row for `(project identity, client)`: owner, enabled flag, canonical `project_root`, environment config path, storage namespace and policy. The binding is the only authority for enablement.
- **Marker**: `<project_root>/.agentic-inquiry/integration.json`, machine-local and gitignored; a fast-path hint for adapters, never authority.
- **Hook error codes**: the closed enum in the response schema. **CLI codes**: the closed set `project_not_onboarded`, `storage_namespace_invalid`, `standalone_plugin_enabled`, `settings_unreadable`, `owner_conflict`, `owner_mismatch`, `project_identity_invalid`, `project_files_invalid`, `policy_invalid`, `memories_failed`, `environment_busy`, `confirmation_declined`, `internal_error`. Every CLI verb answers a ledger that cannot be opened or read within its busy timeout with `environment_busy` naming the errno, and any exception that escapes it with `internal_error` naming only the exception type, both in the envelope, exit 1, stderr silent. **CLI envelope**: with `--json`, `enable`, `disable`, `integration status`, `status`, `purge` and `reconcile` print `{"schema_version": 1, "ok": true, ...verb fields}` on success and `{"schema_version": 1, "ok": false, "errors": [{"code", "message"}], ...the verb's count fields as far as it progressed}` on refusal, exit 1; a count field means the same thing on success and on refusal. One non-refusal exit 1 exists: `reconcile` prints `ok: true` with `failed > 0` (AC17). `purge` is part of the verb surface RFC-0002 accepted; the RFC's erratum records the addition.

## Boundaries

### Always do

- Print the protocol JSON on stdout for every `integration hook` invocation, including refusals, and exit 0 for `ok` or `inert`, 1 for `partial` or `unsupported`, 2 for `error`.
- Keep the ledger module synchronous `sqlite3` (the hook is a short-lived process where an event loop buys nothing) and call it from every async path (`reconcile` and `purge`) only through `asyncio.to_thread`, opening, using and closing each ledger connection inside one `to_thread` call so no `sqlite3.Connection` crosses threads and `check_same_thread` keeps its default, entering and leaving `project_lock` on the calling thread (its `flock` is process-wide); the `ai mcp` server's event loop then never blocks on a ledger busy timeout. This is the one stated exception to the async-at-the-I/O-boundary rule.
- Keep stderr silent on `--version`, `capabilities`, `integration hook`, `integration status` and `status --json`; log at WARNING or above on those paths; convert an escaped exception into an `internal_error` response rather than a traceback (the hook code on `integration hook`, the CLI code of the same name in the envelope on `integration status` and `status --json`; `--version` and `capabilities` are static outputs with no data dependency and no error path).
- Import only the standard library and `sqlite3` on `--version`, `capabilities`, `integration status` and the ledger-only branches of `integration hook`; open the LanceDB environment only inside the deadline-guarded read stage of SessionStart and UserPromptSubmit.
- Resolve every path from the request's `project_root`, never from the current working directory; refuse an artifact whose resolved path (following symlinks) leaves `project_root`.
- Gate in this order: client and event, stdin size and parse, admitted keys, `owner` value, canonical `project_root` and `session_id`, project identity, binding (inert), owner conflict, bounds, artifact confinement, then the exclusion and filter drop of AC9, then event identity, then the policy gate (so a capture without `event_id` is `event_id_required`, never `capture_disabled`). A refused key never reaches the ledger even in an unregistered project.
- Read enablement, owner, policy, storage namespace and the bound `project_root` only from the binding under `INQUIRY_HOME`; the marker is never authority.
- Reuse `validate_file_path`, `PathValidationError` and `validate_project_id` from `agentic_inquiry/mcp/utils/validation.py` for confinement and the storage namespace (that module imports only the standard library once `agentic_inquiry/__init__.py` is side-effect free); the 16-hex identity rule is new and lives in `integration/contract.py`. Prompt text reaches the store only through `StorageFacade.fts_search`, whose query builder sanitises full-text syntax on the FTS search path, primary branch and stale-table retry (the retry fixed in this change; `hybrid_search` still passes a raw query and is a backlog item, unreachable from the hook).
- Read at most `max_hook_input_bytes + 1` bytes from stdin and refuse oversized input before parsing it.
- Own the artifact exclusion floor as a literal pattern tuple in `integration/contract.py` matched case-insensitively with `fnmatch.fnmatchcase` over casefolded values against the project-relative path, the basename and every path component (the connectors' own three-way semantics), and read the environment's connector ignore patterns from the snapshot `enable` stored in the binding's policy; the hook never imports `agentic_inquiry.connectors` or `agentic_inquiry.config`.
- Record every mutation in the ledger before answering, and answer a redelivery from the ledger.
- Treat request payloads, retrieved content and stored memories as data: they never change owner, scope, enablement or policy.

### Ask first

- Any change to `schema_version`, `hook_schema_version`, the status set, the receipt kinds, either closed code set, the exit-code rule or the status precedence.
- Adding a fourth client name or a new lifecycle event.
- Any write into a project's `.claude/`, `.codex/`, `.pi/` or `.agents/` trees.
- Any change to the standalone plugin under `extensions/claude/ai/` beyond documentation.

### Never do

- Forward transcript paths, tool output or hidden reasoning to the runtime, or accept payload keys outside the admitted set.
- Load the embedding model, start a server or watcher, open a network port or download anything inside `integration hook`.
- Create a second durable record for a repeated `event_id`, or invent an identity when the client supplied none.
- Add a dependency to `pyproject.toml` for this feature, or a top-level directory other than `contracts/`.
- Report success on a zero exit alone; every durable claim carries a receipt with a nonempty `durable_id`.
- Write an absolute path into any `integration hook` response string or onto stderr; every path in a hook response is relative to `project_root` (operator verbs such as `ai status` may print the project root).

## Testing Strategy

- **Request validation, budget accounting, rendering, ledger identity, owner rules, capability report:** TDD. Pure functions and a SQLite state machine with compressible invariants; unit and property tests in `plan.md`.
- **The CLI contract as the pack sees it:** goal-based, exercised by black-box integration tests (`tests/integration/test_afp_lifecycle_contract.py`) that run `python -m agentic_inquiry.cli` in a subprocess with JSON on stdin and assert response shape against the schemas, exit code, stderr silence and wall time. One white-box seam is permitted in that file: the AC27 sweep test edits `integration_events` through the ledger schema the plan's Design section owns, so that memory items are reachable only through `task_id`; every other test that touches the ledger file does so without naming a ledger table (holding a lock, reading raw bytes, querying `sqlite_master`).
- **Import hygiene and latency:** goal-based, exercised by subprocess tests that assert `sys.modules` contents and wall time.
- **Recall, evidence and reconcile against a real LanceDB environment:** goal-based integration tests on an onboarded temporary project with the hashing embedder; the database is real, not mocked (CONVENTIONS section 4).
- **`ai mcp` and the maintenance tick:** goal-based; dispatch asserted in-process with the server entry monkeypatched; the tick asserted by the ledger transition it produces.
- **Bind address selection:** TDD on `bind_host`, `MCPServer.run` and `MCPServer.run_async`; goal-based grep for the call sites.
- **End to end through the AFP pack:** manual QA owned by task T13, recorded in `notes/afp-pack-journey.md`. Verifiable in this change: Claude Code payloads replayed through the AFP bridge with pack 0.3.0 in a scratch repository. - [x] AC5 Status is a total function with this precedence: `unsupported` (client or event) over `error` (a refusal) over `inert` (no enabled binding) over `partial` over `ok`. A refusal is a `ContractError` raised by a gate; `finalize(response, refusal)` takes it as an explicit input and never infers it from the `errors` list. Six codes are advisory and never raise the status: `durable_store_absent` (carried by an `inert` response), `budget_exhausted` (carried by a `partial` one), `ledger_unavailable` when the request carried no observations and no artifacts (carried by a `partial` one), `artifact_ignored` (carried by any status), `event_purged` (carried by any status) and `capture_exhausted` (carried by SessionStart while an exhausted row exists); `ledger_unavailable` on a request that carried observations or artifacts is a refusal whatever the event (AC23). A response is `partial` when any receipt belongs to a ledger row that is not `committed`, when any row for `(project identity, client)` is in state `pending`, `committing` or `failed` with fewer than 3 attempts (an exhausted row, `failed` at 3 attempts, no longer forces `partial`), when the ledger could not be opened or read inside the deadline (`ledger_unavailable`), or when the read stage was skipped for the deadline (`budget_exhausted`); a stage disabled by policy is not a skip; a row in state `purged` (AC27 step zero) is terminal like `committed` and never forces `partial`. When a refusal is present it is `errors[0]` and advisory errors follow it. The event that creates a queued row therefore returns `partial`, exit 1. Exit codes: 0 for `ok` and `inert`, 1 for `partial` and `unsupported`, 2 for `error`.
